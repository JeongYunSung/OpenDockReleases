# Product Roast

막연히 별로라고 말하지 않고 첫인상, 가치 제안, 정보 구조, CTA, 신뢰와 모바일 흐름을 근거로 비평합니다. 유지해야 할 장점도 함께 찾아 실행 가능한 개선 순서를 만듭니다.

## 이런 때 사용하세요

- 랜딩이나 제품 화면의 약점을 빠르게 찾을 때
- 사용자가 가치와 다음 행동을 이해하는지 볼 때
- 리디자인 전에 우선순위를 정할 때

## AI에서 이렇게 사용하세요

AI에서 `$opendock-product-roast` 스킬을 선택한 뒤 자연어로 요청하세요. 스킬 선택 기능이 없는 AI에서는 요청에 “Product Roast 기준으로”라고 적어도 됩니다.

### 요청 예시

> 이 랜딩 페이지를 처음 방문한 고객 관점에서 솔직하게 비평해줘.

> 전환을 막는 문제 5개와 유지해야 할 장점 3개를 근거와 함께 정리해줘.

## 검토가 필요할 때

요청에 `검토해줘`라고 덧붙이면 AI가 이 Dock의 기준으로 현재 결과물만 다시 읽고 빠진 내용과 모순을 고칩니다. 별도의 무거운 하네스나 프로젝트 전체 검사는 실행하지 않습니다.

## 사용 후 얻는 것

- 근거와 심각도가 있는 문제 목록
- 당장 고칠 항목과 나중에 실험할 항목
- 유지할 강점과 리디자인 방향

# Product Designer

막연한 아이디어나 화면 요청을 바로 그리는 대신, 제품 디자이너처럼 사용자 문제와 범위를 먼저 좁히고 여러 방향을 비교합니다. 선택한 방향은 흐름, 상태, 반응형, 접근성, 데이터 조건까지 설계한 뒤 검증 가능한 프로토타입과 개발 전달로 이어집니다.

외부 디자인 도구가 없어도 전체 워크플로우가 동작합니다. 작은 요청은 한 Product Designer가 직접 처리하고, 복잡한 작업은 독립된 조사·흐름·접근성·prototype 검토만 조건부로 나눈 뒤 최종 Product Designer가 다시 합칩니다. 작업을 멈췄다가 Codex와 Claude Code 사이를 옮겨도 결정, 미해결 항목과 다음 행동을 같은 세션에서 이어갈 수 있습니다.

## 이런 때 사용하세요

- 아이디어는 있지만 사용자, 범위와 성공 조건이 아직 모호할 때
- 기존 제품의 DESIGN.md와 화면 문법을 지키며 새 기능을 설계할 때
- 시안만 만드는 대신 loading, empty, error와 권한 상태까지 정리할 때
- 디자이너와 개발자 사이의 반복 설명을 줄이고 싶을 때
- 긴 설계 작업을 중단했다가 다른 AI에서도 이어가고 싶을 때

## AI에서 이렇게 사용하세요

AI에서 $opendock-product-designer 스킬을 선택하고 원하는 결과를 자연어로 요청하세요. 이미 결정된 내용은 다시 묻지 않고, 실제 설계를 바꾸는 가장 중요한 질문을 한 번에 하나씩 드립니다.

### 요청 예시

> 운영자가 매일 확인하는 정산 대시보드를 설계하고 싶어. 기존 DESIGN.md를 먼저 읽고 모호한 부분부터 한 번에 하나씩 물어봐줘.

> 이 회원가입 흐름을 모바일 중심으로 다시 설계해줘. 두 가지 방향을 비교한 뒤 선택한 안을 상태별 화면과 개발 acceptance까지 이어줘.

> 지난 Product Designer 세션을 이어서 진행해줘. 바뀐 DESIGN.md가 영향을 주는 부분만 다시 확인하고 다음 행동부터 시작해줘.

## 검토가 필요할 때

요청에 검토를 덧붙이면 현재 설계와 결과물만 다시 확인합니다. 목표와 범위, 선택 근거, 모든 적용 상태, DESIGN.md 일치, 접근성, 검증 근거와 미해결 위험을 살피며 실행하지 않은 검사를 통과로 꾸미지 않습니다.

## 사용 후 얻는 것

- 사용자와 문제, 목표, 범위가 합의된 제품 프레임
- 의미 있게 다른 설계 방향과 선택 근거
- 흐름, 정보 위계, 상태, 반응형과 접근성을 포함한 specification
- 검증 결과와 미해결 위험이 연결된 prototype 기록
- 개발자가 재해석할 일을 줄이는 중립적인 handoff
- Codex와 Claude Code에서 이어갈 수 있는 간결한 세션 checkpoint

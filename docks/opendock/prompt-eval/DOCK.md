# Prompt Eval

몇 번 잘 나온 결과만 보고 프롬프트가 좋아졌다고 판단하지 않고 대표 입력, 실패 사례와 평가 기준을 정해 비교합니다. 프롬프트 변경이 품질, 비용, 속도에 미치는 영향을 함께 볼 수 있습니다.

## 이런 때 사용하세요

- 프롬프트 수정 전후의 품질을 비교할 때
- 여러 모델 중 작업에 맞는 모델을 고를 때
- 자주 실패하는 입력을 회귀 사례로 남길 때

## 설치되는 도구

- Promptfoo CLI를 프로젝트 전용으로 준비합니다.
- 사용할 수 있는 명령: `promptfoo`
- 도구는 현재 프로젝트에서 OpenDock이 추적하므로 다른 프로젝트의 전역 환경과 섞이지 않습니다.

## AI에서 이렇게 사용하세요

AI에서 `$opendock-prompt-eval` 스킬을 선택한 뒤 자연어로 요청하세요. 스킬 선택 기능이 없는 AI에서는 요청에 “Prompt Eval 기준으로”라고 적어도 됩니다.

### 요청 예시

> 이 요약 프롬프트의 평가 기준과 대표 테스트 입력 20개를 만들어줘.

> 두 프롬프트를 같은 데이터로 평가해서 품질, 비용, 실패 유형을 비교해줘.

## 사용 후 얻는 것

- 반복 실행 가능한 프롬프트 평가 묶음
- 성공과 실패를 보여주는 비교 결과
- 다음 버전에서도 다시 확인할 회귀 사례

## 알아둘 점

외부 모델을 평가하려면 해당 제공자의 인증과 비용 설정이 별도로 필요할 수 있습니다.

# UX Audit

취향으로 좋고 나쁨을 말하지 않고 사용자가 목표를 달성하는 과정에서 막히는 지점을 봅니다. 정보 구조, 피드백, 오류 회복, 접근성과 모바일 사용성을 함께 분석합니다.

## 이런 때 사용하세요

- 기존 제품의 사용 불편을 체계적으로 찾을 때
- 온보딩이나 결제 흐름의 이탈 원인을 볼 때
- 리디자인 전에 문제 우선순위를 정할 때

## AI에서 이렇게 사용하세요

AI에서 `$opendock-ux-audit` 스킬을 선택한 뒤 자연어로 요청하세요. 스킬 선택 기능이 없는 AI에서는 요청에 “UX Audit 기준으로”라고 적어도 됩니다.

### 요청 예시

> 이 회원가입 흐름을 처음 쓰는 사용자 관점에서 분석해줘.

> 모바일 결제 화면의 문제를 근거, 심각도, 영향받는 사용자와 개선안으로 정리해줘.

## 검토가 필요할 때

요청에 `검토해줘`라고 덧붙이면 AI가 이 Dock의 기준으로 현재 결과물만 다시 읽고 빠진 내용과 모순을 고칩니다. 별도의 무거운 하네스나 프로젝트 전체 검사는 실행하지 않습니다.

## 사용 후 얻는 것

- 근거와 심각도가 있는 UX 문제 목록
- 사용자 목표와 연결된 개선안
- 빠른 수정과 구조적 개선을 나눈 우선순위

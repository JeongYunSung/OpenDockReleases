# QA Ultrawork

정상 동작 한 번만 확인하지 않고 신규 사용자, 기존 데이터, 실패, 권한, 플랫폼과 반복 실행을 봅니다. 강한 검수를 요청하면 현재 변경의 위험에 맞춰 테스트 범위를 넓히고 실패를 재현 가능한 근거로 남깁니다.

## 이런 때 사용하세요

- 새 기능의 테스트 시나리오를 만들 때
- 업데이트와 제거, 충돌 같은 엣지케이스를 확인할 때
- 보안, 성능, 접근성까지 포함한 품질 검수가 필요할 때

## AI에서 이렇게 사용하세요

AI에서 `$opendock-qa-ultrawork` 스킬을 선택한 뒤 자연어로 요청하세요. 스킬 선택 기능이 없는 AI에서는 요청에 “QA Ultrawork 기준으로”라고 적어도 됩니다.

### 요청 예시

> 이 설치 기능의 정상, 기존 프로젝트, 충돌, 네트워크 실패 테스트를 만들어줘.

> 이번 변경을 ultrawork로 검수하고 실제 사용자 흐름에서 실패하는 사례를 찾아 고쳐줘.

## 검수 강도

- 평소 요청에서는 지금 만들거나 수정한 결과물에 필요한 기준만 적용해 빠르게 작업합니다.
- 요청에 `검수` 또는 `ultrawork`를 넣으면 현재 결과물에 강한 하네스와 AI 검토를 적용하고, 실패 항목을 고친 뒤 다시 확인합니다.
- 프로젝트 전체 검사는 사용자가 전체 범위를 명확히 요청한 경우에만 실행합니다. 관련 없는 기존 파일 때문에 작업을 늦추지 않습니다.

## 사용 후 얻는 것

- 위험 우선순위에 따른 테스트 시나리오
- 재현 단계와 기대 결과가 명확한 결함
- 현재 변경 범위의 회귀·보안·접근성 검수 결과

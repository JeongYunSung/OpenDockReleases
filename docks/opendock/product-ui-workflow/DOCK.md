# Product UI Workflow

모호한 제품 아이디어를 질문으로 정리한 뒤 사용자 흐름, 디자인 시스템, 재사용 컴포넌트와 검증된 화면으로 완성합니다. 기존 제품의 규칙을 우선하면서 Storybook을 작업대와 테스트 기준으로 사용합니다.

## 이런 때 사용하세요

- 새 기능을 만들기 전에 사용자 흐름과 완료 조건부터 정리할 때
- 기존 화면을 디자인 시스템과 Storybook 컴포넌트에 맞춰 개선할 때
- Figma나 기준 화면과 구현 결과가 계속 어긋나는 문제를 줄일 때
- 로딩·오류·빈 상태·접근성까지 포함한 UI를 만들 때

## 설치되는 도구

- `oh-my-design`과 `omd`: 프로젝트의 디자인 결정, 토큰과 컴포넌트 계약을 관리합니다.
- Storybook과 Storybook MCP는 프로젝트마다 프레임워크와 버전이 달라 자동 설치하지 않습니다. 실제 작업에서 기존 설정을 확인한 뒤 필요한 경우에만 추가합니다.

## AI에서 이렇게 사용하세요

Codex에서는 `$opendock-product-ui-workflow`, Claude Code에서는 `/opendock-product-ui-workflow`를 선택하고 만들 기능, 참고 화면이나 현재 프로젝트를 알려주세요.

### 요청 예시

> $opendock-product-ui-workflow 예약 변경 화면을 설계하고 구현해줘. 먼저 결정이 필요한 부분만 질문하고 모바일 오류 상태까지 Storybook으로 검증해줘.

> $opendock-product-ui-workflow 이 Figma 화면을 기존 컴포넌트로 구현해줘. 데스크톱과 모바일 스크린샷을 비교하고 예상하지 않은 차이를 정리해줘.

> /opendock-product-ui-workflow 기존 결제 화면을 점검하고 Storybook 상태와 접근성 테스트가 빠진 부분을 보완해줘.

## 사용 후 얻는 것

- 범위·가정·비목표가 분명한 제품 UI 브리프
- 성공·오류·로딩·빈 상태를 포함한 독자 작성 사용자 시나리오와 BDD 조건
- 근거가 연결된 디자인 토큰과 컴포넌트 계약
- 재사용 가능한 컴포넌트, Story와 조합된 실제 화면
- 동작·접근성·반응형·시각 차이 검증 결과와 남은 위험

## 검토가 필요할 때

“현재 결과를 다시 검토해줘”라고 요청하면 이번 작업에서 변경된 화면과 Story만 기준 문서에 직접 대조합니다. 자동으로 기준 이미지를 승인하거나 커밋·배포하지 않으며, 확인할 수 없는 항목은 통과로 표시하지 않습니다.

## 알아둘 점

Storybook MCP의 AI 기능은 현재 preview이며 프레임워크별 문서 도구 지원 범위가 다릅니다. Chromatic 시각 회귀는 별도 계정과 프로젝트 토큰이 필요합니다. 이 Dock은 토큰을 저장하지 않고, 없을 때는 로컬 스크린샷 비교와 명시적인 미검증 결과로 대체합니다.

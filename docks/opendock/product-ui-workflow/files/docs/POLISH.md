# Visual And Korean Copy Polish

Polish runs after behavior, scenarios and accessibility are stable.

## Visual review

Read the brief before applying taste. Check hierarchy, spacing rhythm, typography, density, component reuse and whether the layout matches the product domain. Flag generic AI defaults only when they are unsupported by the brief: decorative card grids, oversized marketing headings in operational UI, arbitrary gradients, inconsistent radius systems, invented icons and motion without interaction value.

Do not replace an existing system merely to look distinctive. Reuse its tokens and components. A visual recommendation that conflicts with product behavior, accessibility or an approved baseline must return to the owning decision instead of being applied automatically.

## Korean copy review

Review only user-facing Korean prose selected in the current scope. Remove translationese, mechanical parallelism, redundant headings, repetitive sentence endings and unsupported promotional language. Preserve facts, numbers, names, legal meaning, user intent and action consequences.

Do not rename code identifiers, translation keys, analytics events or component APIs. Do not change an accessible name independently of its visible control label. For destructive, financial, medical, legal or permission-changing actions, clarity and consequence disclosure outrank conversational tone.

Report meaningful copy changes for human review. Do not claim text was written by a human or designed to bypass authorship detection.

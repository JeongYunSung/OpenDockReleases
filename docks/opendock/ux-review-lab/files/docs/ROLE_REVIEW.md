# 역할별 UX 리뷰

일반 사용성 관점을 바탕으로 최대 세 가지 역할의 질문을 적용합니다. 역할은 사고 관점이며 실사용자 표본, 자격 인증 또는 독립된 서브에이전트를 의미하지 않습니다. 기본 실행에는 에이전트 분할이 필요하지 않습니다.

## 역할 선택

사용자가 지정한 역할을 우선합니다. 지정이 없으면 UX/UI 디자이너, 기획자, 개발자 관점을 사용합니다. 세 역할을 넘게 요청하면 목적에 가까운 세 역할을 제안하고 확인합니다. 임의로 일부 역할을 검토한 뒤 전부 검토했다고 말하지 않습니다.

사용자가 일반 사용성 검토까지 명시적으로 제외했다면 그 제한을 따릅니다. 특정 연령대 등 사용자 관점을 요청해도 그 집단을 실제로 조사했거나 대표한다고 주장하지 않습니다.

## 역할별 질문

| 관점 | 핵심 질문 | 단정하지 않을 것 |
| --- | --- | --- |
| 일반 사용성 | 목적·다음 행동·현재 상태를 이해하는가? 실수를 되돌릴 수 있는가? | 실제 이탈률이나 성공률 |
| UX/UI 디자이너 | 위계와 CTA가 맞는가? 상태 표현과 화면 간 규칙이 일관되는가? | 이미지 하나로 반응형·접근성 검증 완료 |
| 기획자 | 성공·실패 조건과 예외 정책을 이해할 수 있는가? 다음 단계와 복구 경로는 무엇인가? | 제공되지 않은 업무 정책 |
| 개발자 | 데이터 지연·빈 결과·실패·중복 행동에 필요한 상태가 설명되는가? | 소스나 실행 근거 없는 API 결함 |

다른 역할을 지정하면 현재 사용자 목표에 관련된 질문으로 대체합니다. 역할별로 새로운 근거나 판단이 없는 항목은 반복하지 않습니다.

## 통합 우선순위

- P0: 핵심 작업을 막거나 데이터 손실 등 큰 피해로 이어지는 구체적 근거가 있는 문제. 화면만으로 확정할 수 없다면 심각도와 별개로 미검증 위험임을 표시합니다.
- P1: 목표 달성에 혼란이나 불필요한 작업을 만드는 문제. 사용성 테스트 전 우선 개선할 후보입니다.
- P2: 흐름을 막지는 않지만 일관성·가독성·시각적 완성도를 높일 수 있는 문제입니다.

하나의 문제에는 하나의 항목을 만들고 관련 역할을 필요할 때만 표시합니다. 관점이 충돌하면 역할 수로 투표하지 말고 사용자 목표와 관찰 근거에 따라 절충안을 설명합니다. 근거가 부족한 판단은 추가 확인으로 남깁니다. 각 항목에 위치, 근거, 영향, 개선안을 포함하고 확인한 장점도 보존합니다.

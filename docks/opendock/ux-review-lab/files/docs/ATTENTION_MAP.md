# AI 예상 주목도 맵

화면 요소의 크기·대비·색·위치·정보 위계를 근거로 시각적 주목 순서를 추정합니다. 실제 시선이나 사용자 행동을 측정하는 기능이 아닙니다. 일반적인 버튼 UX 질문만으로 이미지를 만들지 않고, 주목도 시각화 또는 예상 시선 분석을 요청했을 때 적용합니다.

## 입력과 범위

원본 화면을 확인할 수 있는지, 캡처와 이미지 편집 도구가 있는지 먼저 확인합니다. 사용자가 지정한 화면과 범위가 우선입니다.

범위 지정이 없으면 화면 세 개까지 검토합니다. 더 많으면 선택한 핵심 세 화면과 제외 범위를 밝히고 나머지 분석 여부를 안내합니다. 긴 페이지는 실제 화면 크기의 구간으로 나눠 봅니다. 영상은 시작·주요 전환·완료 장면 등 세 개에서 다섯 개의 대표 장면과 시점을 표시합니다. 도구로 확인하지 못한 장면은 추정해 채우지 않습니다.

## 이미지가 가능한 경우

원본과 비교 가능한 별도 오버레이를 만듭니다. 원본의 문구, 위치, UI 상태를 재디자인하지 않습니다. 생성 도구가 원본을 정확히 유지하지 못하면 정확한 오버레이라고 제시하지 말고 한계를 밝힌 텍스트 설명으로 전환합니다.

빨강은 가장 먼저 주목될 것으로 예상되는 영역, 주황은 그 다음, 노랑은 보조 영역으로 사용합니다. 색상만으로 구별하지 않도록 숫자 1·2·3과 텍스트 범례를 함께 표시합니다. 핵심 정보가 가려지지 않게 하고, 번호가 붙은 요소별 판단 근거를 설명합니다.

의도한 핵심 요소와 예상 주목 순서가 다르면 위치·크기·대비 등을 조정하는 구체적 대안을 제시합니다. 확률, 체류시간, 실험 참여자 수처럼 측정으로 오해될 숫자는 만들지 않습니다.

## 도구가 부족한 경우

- 이미지를 읽을 수 있지만 편집할 수 없으면 요소명·위치·예상 순서·판단 근거를 텍스트로 제공합니다.
- 원본 자체를 읽을 수 없으면 스크린샷이나 지원되는 형식의 업로드를 요청합니다. 화면을 보지 않고 주목 순서를 만들지 않습니다.
- 생성하지 않은 캡처나 이미지 파일의 경로를 결과로 제시하지 않습니다.

## 결과 고지와 보관

시각화 또는 텍스트 결과에 “AI의 시각적 주목도 추정이며 실제 사용자 시선을 측정한 결과가 아닙니다”라고 명시합니다. 사용자 테스트와 시선 추적 실험을 대신하는 근거로 사용하지 않습니다.

주목도 맵 요청은 현재 응답에 필요한 파생 이미지 제작을 허용하지만 원본 덮어쓰기, Git 추가, 외부 게시, 예시 재사용을 허용하지 않습니다. 도구가 임시 결과 파일을 만들면 현재 응답용 결과임을 구분하고, 별도 보관은 사용자 요청을 따릅니다.

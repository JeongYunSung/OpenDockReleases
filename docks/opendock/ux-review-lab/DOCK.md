# UX 리뷰랩

화면을 보여주고, 사용자가 어디서 헷갈릴지 먼저 확인하세요. 빠른 UX 점검과 디자이너·기획자·개발자 관점의 리뷰를 한 번에 받아 개선 순서를 정할 수 있습니다.

## 이런 때 사용하세요

- Figma 시안이나 스크린샷을 개발에 넘기기 전에 점검할 때
- 가입·예약·결제 화면에서 다음 행동과 오류 안내가 분명한지 확인할 때
- 프로토타입의 흐름을 여러 역할의 관점에서 살펴보고 싶을 때
- 중요한 버튼이 눈에 띄는지 예상 주목 순서를 비교할 때

## AI에서 이렇게 사용하세요

Dock을 설치한 프로젝트에서 화면이나 링크와 함께 요청하세요. Codex에서는 `$opendock-ux-review-lab`, Claude Code에서는 `/opendock-ux-review-lab`으로 호출합니다. 스킬 선택 기능이 없는 AI에는 “UX 리뷰랩 기준으로”라고 요청하세요.

기본은 빠른 UX 점검과 역할별 리뷰입니다. 기능을 지정하면 선택한 기능만 진행하며, 주목도 맵은 요청할 때만 만듭니다. 리뷰팀은 한 AI가 역할별 관점을 적용하는 방식이며 실제 사람의 평가나 독립된 여러 에이전트의 합의를 뜻하지 않습니다.

### 요청 예시

> $opendock-ux-review-lab 이 모바일 가입 화면을 점검해줘. 혼란스러운 문구와 다음 행동을 중심으로 개선 순서를 알려줘.

> $opendock-ux-review-lab 이 Figma 프레임을 디자이너와 개발자 관점으로만 리뷰해줘. 원본은 수정하지 마.

> $opendock-ux-review-lab 첨부 화면의 AI 예상 주목도 맵만 만들어줘. 구매 버튼과 다른 요소 중 무엇이 먼저 보일지 비교해줘.

> /opendock-ux-review-lab 이 Figma 프레임을 빠른 UX 점검만 해줘. 문제의 근거와 개선 순서를 알려주고 원본은 수정하지 마.

## 사용 후 얻는 것

- 한 줄 결론과 잘 전달되는 부분, 혼란이 예상되는 부분
- 중복 의견을 합친 문제 목록과 P0·P1·P2 개선 우선순위
- 관찰 근거, 구체적인 개선안, 실제 사용자 테스트에서 확인할 질문
- 요청한 경우에만 예상 주목도 이미지 또는 텍스트 기반 주목 순서

기본 결과는 채팅으로 제공하며 코드나 Figma 파일을 자동으로 만들거나 수정하지 않습니다. 결과를 파일로 남기려면 별도로 요청하세요.

## 설치 범위와 도구

Codex와 Claude Code가 읽는 스킬과 가이드를 선택한 프로젝트 안에만 설치합니다. 사용자 홈의 전역 스킬, 전역 패키지, 백그라운드 서비스는 설치하지 않습니다. macOS와 Windows에 같은 내용을 제공합니다. Claude 웹 채팅이나 Cowork에 스킬을 업로드하는 패키지는 아닙니다.

Figma 링크를 읽으려면 연결된 Figma MCP가 필요합니다. 웹·영상 확인과 주목도 이미지 제작은 현재 AI 환경의 도구 지원에 따라 달라집니다. 이 Dock이 도구나 인증을 대신 설치하지는 않습니다. 링크를 읽을 수 없으면 스크린샷을 요청하고, 이미지 편집 기능이 없으면 텍스트로 예상 순서를 설명합니다.

예상 주목도는 실제 시선 추적 결과가 아니며, UX 리뷰는 실사용자 조사나 접근성 인증을 대신하지 않습니다.

## 검토가 필요할 때

“리뷰 결과를 다시 검토해줘”라고 요청하면 AI가 현재 결과를 가이드와 직접 비교해 빠진 근거와 중복·모순을 확인합니다. 별도 하네스, 반복 검증 루프, 프로젝트 전체 검사는 실행하지 않습니다.

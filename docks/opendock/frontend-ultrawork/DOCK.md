# Frontend Ultrawork

화면이 보이는 것만으로 완료하지 않고 로딩, 빈 상태, 오류, 키보드 사용, 반응형과 비동기 실패까지 확인합니다. 강한 검수를 요청하면 현재 변경한 컴포넌트와 페이지를 lint, typecheck, test, build 기준으로 엄격하게 봅니다.

## 이런 때 사용하세요

- React나 Next.js 화면과 기능을 구현할 때
- API 연동 화면의 로딩과 오류 처리를 점검할 때
- 타입, 접근성, 번들 크기와 회귀를 검수할 때

## AI에서 이렇게 사용하세요

AI에서 `$opendock-frontend-ultrawork` 스킬을 선택한 뒤 자연어로 요청하세요. 스킬 선택 기능이 없는 AI에서는 요청에 “Frontend Ultrawork 기준으로”라고 적어도 됩니다.

### 요청 예시

> 검색과 필터가 있는 상품 목록 화면을 상태별 UI까지 구현해줘.

> 이번 프론트엔드 변경을 ultrawork로 검수해서 타입 오류, 접근성, 모바일, 비동기 실패를 고쳐줘.

## 검수 강도

- 평소 요청에서는 지금 만들거나 수정한 결과물에 필요한 기준만 적용해 빠르게 작업합니다.
- 요청에 `검수` 또는 `ultrawork`를 넣으면 현재 결과물에 강한 하네스와 AI 검토를 적용하고, 실패 항목을 고친 뒤 다시 확인합니다.
- 프로젝트 전체 검사는 사용자가 전체 범위를 명확히 요청한 경우에만 실행합니다. 관련 없는 기존 파일 때문에 작업을 늦추지 않습니다.

## 사용 후 얻는 것

- 사용 상태를 빠뜨리지 않은 프론트엔드 구현
- 타입과 접근성을 포함한 자동화 테스트
- 현재 변경 범위의 빌드·성능·회귀 검수 결과

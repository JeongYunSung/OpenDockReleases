# README Doctor

섹션을 많이 넣는 것보다 누구를 위한 제품인지, 가장 빠른 사용법이 무엇인지, 실패하면 어디를 봐야 하는지를 선명하게 만듭니다. 실제 명령과 코드 상태를 확인해 오래된 설명도 찾습니다.

## 이런 때 사용하세요

- 새 오픈소스 프로젝트의 README를 만들 때
- 설치와 빠른 시작이 어렵다는 피드백을 받았을 때
- 코드와 맞지 않는 오래된 문구를 정리할 때

## AI에서 이렇게 사용하세요

AI에서 `$opendock-readme-doctor` 스킬을 선택한 뒤 자연어로 요청하세요. 스킬 선택 기능이 없는 AI에서는 요청에 “README Doctor 기준으로”라고 적어도 됩니다.

### 요청 예시

> 이 저장소를 분석해서 처음 방문한 사람이 이해할 README를 작성해줘.

> 현재 README의 명령을 실제 코드와 비교하고 틀린 부분과 빠진 문제 해결 내용을 고쳐줘.

## 검토가 필요할 때

요청에 `검토해줘`라고 덧붙이면 AI가 이 Dock의 기준으로 현재 결과물만 다시 읽고 빠진 내용과 모순을 고칩니다. 별도의 무거운 하네스나 프로젝트 전체 검사는 실행하지 않습니다.

## 사용 후 얻는 것

- 제품 가치와 대상이 선명한 첫 화면
- 5분 안에 따라 할 수 있는 빠른 시작
- 현재 코드와 일치하는 설치·사용·문제 해결 안내

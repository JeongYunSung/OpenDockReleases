# DevOps Ultrawork

설정 파일이 문법상 맞는지뿐 아니라 장애가 났을 때 되돌릴 수 있는지, 비밀정보와 과도한 권한이 없는지, 운영자가 상태를 확인할 수 있는지까지 봅니다.

## 이런 때 사용하세요

- Terraform, Kubernetes, Helm 설정을 바꿀 때
- CI/CD와 배포 절차를 새로 만들 때
- 공개 노출, latest 태그, 자원 제한 누락을 잡을 때

## AI에서 이렇게 사용하세요

AI에서 `$opendock-devops-ultrawork` 스킬을 선택한 뒤 자연어로 요청하세요. 스킬 선택 기능이 없는 AI에서는 요청에 “DevOps Ultrawork 기준으로”라고 적어도 됩니다.

### 요청 예시

> 이 서비스를 Kubernetes에 배포할 설정과 롤백 절차를 만들어줘.

> 이번 인프라 변경을 ultrawork로 검수해서 공개 노출과 권한, 비용, 복구 위험을 고쳐줘.

## 검수 강도

- 평소 요청에서는 지금 만들거나 수정한 결과물에 필요한 기준만 적용해 빠르게 작업합니다.
- 요청에 `검수` 또는 `ultrawork`를 넣으면 현재 결과물에 강한 하네스와 AI 검토를 적용하고, 실패 항목을 고친 뒤 다시 확인합니다.
- 프로젝트 전체 검사는 사용자가 전체 범위를 명확히 요청한 경우에만 실행합니다. 관련 없는 기존 파일 때문에 작업을 늦추지 않습니다.

## 사용 후 얻는 것

- 검증 가능한 인프라와 배포 설정
- 장애 시 사용할 롤백 및 운영 절차
- 보안, 비용, 가용성 위험에 대한 현재 변경 범위의 검수 결과

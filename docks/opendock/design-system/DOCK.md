# Design System

화면마다 다른 값과 컴포넌트가 늘어나는 문제를 줄이기 위해 디자인 토큰과 사용 규칙을 만듭니다. 기존 제품을 분석해 시작할 수도 있고, 새 제품의 기본 체계를 처음부터 정할 수도 있습니다.

## 이런 때 사용하세요

- 제품의 색상과 타이포그래피 규칙을 정할 때
- 중복 컴포넌트를 정리하고 이름을 통일할 때
- 디자인과 코드가 같은 토큰을 사용하게 만들 때

## AI에서 이렇게 사용하세요

AI에서 `$opendock-design-system` 스킬을 선택한 뒤 자연어로 요청하세요. 스킬 선택 기능이 없는 AI에서는 요청에 “Design System 기준으로”라고 적어도 됩니다.

### 요청 예시

> 현재 화면을 분석해서 색상, 타이포그래피, 간격 토큰 초안을 만들어줘.

> 버튼 8종을 상태와 용도 기준으로 정리하고 컴포넌트 규칙을 제안해줘.

## 검토가 필요할 때

요청에 `검토해줘`라고 덧붙이면 AI가 이 Dock의 기준으로 현재 결과물만 다시 읽고 빠진 내용과 모순을 고칩니다. 별도의 무거운 하네스나 프로젝트 전체 검사는 실행하지 않습니다.

## 사용 후 얻는 것

- 역할이 분명한 디자인 토큰
- 컴포넌트 상태와 사용 기준
- 새 화면에서도 재사용할 수 있는 일관성 규칙

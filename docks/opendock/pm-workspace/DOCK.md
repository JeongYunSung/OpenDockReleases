# PM Workspace

회의에서 나온 생각을 기능 목록으로 바로 옮기지 않고 문제, 사용자, 성공 기준과 제외 범위를 먼저 정리합니다. 개발과 디자인이 바로 질문하고 실행할 수 있는 제품 문서를 만드는 데 사용합니다.

## 이런 때 사용하세요

- 아이디어를 PRD로 구체화할 때
- 요구사항과 acceptance criteria를 정리할 때
- 우선순위와 의사결정 기록을 남길 때

## AI에서 이렇게 사용하세요

AI에서 `$opendock-pm-workspace` 스킬을 선택한 뒤 자연어로 요청하세요. 스킬 선택 기능이 없는 AI에서는 요청에 “PM Workspace 기준으로”라고 적어도 됩니다.

### 요청 예시

> 고객 문의 자동 분류 기능을 PRD와 사용자 이야기로 정리해줘.

> 이 요구사항에서 빠진 예외 상황과 모호한 완료 조건을 찾아 고쳐줘.

## 검토가 필요할 때

요청에 `검토해줘`라고 덧붙이면 AI가 이 Dock의 기준으로 현재 결과물만 다시 읽고 빠진 내용과 모순을 고칩니다. 별도의 무거운 하네스나 프로젝트 전체 검사는 실행하지 않습니다.

## 사용 후 얻는 것

- 문제와 성공 기준이 명확한 PRD
- 검증 가능한 acceptance criteria
- 범위, 우선순위, 결정 이유가 남는 실행 문서
